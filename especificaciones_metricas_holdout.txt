     interpretables son los perfiles sobre datos nuevos (sección 8).

--------------------------------------------------------------------------------
7. MÉTRICAS DE CATBOOST (supervisado)
--------------------------------------------------------------------------------

Matriz de confusión (labels=[0,1]):
    TN  FP
    FN  TP
  confusion_matrix(y, pred, labels=[0,1]).ravel() -> tn, fp, fn, tp

Métricas principales (las mismas del notebook: accuracy, error, precision,
recall, F1, F2, ROC AUC):

  Métrica               Fórmula / función                          Nota
  --------------------  -----------------------------------------  -----------------------
  Accuracy              (TP+TN)/(TP+TN+FP+FN)                      accuracy_score
  Tasa de error         1 - Accuracy                               como en el notebook
  Precision (clase 1)   TP/(TP+FP)                                 precision_score
  Recall / Sensibilidad TP/(TP+FN)                                 recall_score. Clave
                        (clase 1)                                  clínicamente: FN = caso
                                                                   de dengue no detectado
  Especificidad         TN/(TN+FP)                                 recall de la clase 0
  F1                    2*P*R/(P+R)                                f1_score (métrica con la
                                                                   que se tuneó el umbral)
  F2                    fbeta_score(beta=2)                        pondera más el recall
                                                                   (usada en el scoring CV)
  ROC AUC               roc_auc_score(y, proba)                    con probabilidades
  Umbral usado          model.best_threshold_                      informativo

Métricas complementarias (recomendadas):
  - Valor predictivo negativo (NPV) = TN/(TN+FN)
  - Balanced accuracy               = (Recall + Especificidad)/2
  - PR AUC (average_precision_score(y, proba))
  - MCC (matthews_corrcoef)
  - Brier score (brier_score_loss(y, proba))  -> calidad de las probabilidades
  - Reporte por clase: classification_report(y, pred, digits=4, output_dict=True)
    (precision, recall, f1 y support para clase 0 y 1, macro y weighted avg)
  - Soporte: n total, n positivos, n negativos, % positivos.

Curvas (para graficar en la web):
  - ROC: roc_curve(y, proba) -> fpr, tpr (+ AUC)
  - Precision-Recall: precision_recall_curve(y, proba)
  - Calibración (opcional): calibration_curve(y, proba, n_bins=10)
  - Matriz de confusión (como en el notebook, etiquetas "No Dengue (0)" y
    "Dengue (1)").

Intervalos de confianza (muy recomendado porque el hold-out es chico, del
orden de unos pocos cientos de filas):
  - Bootstrap con 1000 remuestreos estratificados de las filas, IC 95% (percentiles
    2.5 y 97.5) para Recall, Precision, F1, F2 y ROC AUC. Usar semilla fija.

Métricas por subgrupo (si existen las columnas, y n >= 30 por subgrupo):
  - Por source (2025 vs 2026): motivo -> Fever se definió distinto en cada fuente
    (en 2026 es Body_Temperature > 38; en 2025 viene directa).
  - Por Gender.
  Reportar al menos Recall, Precision, F1, ROC AUC y n de cada subgrupo.

Comparación contra desarrollo:
  Guardar en metadata.json las métricas de CV (media ± desvío) y de test del
  notebook, y devolver "delta = hold-out - referencia" para F1, Recall,
  Precision y ROC AUC. Una caída fuerte en el hold-out indica sobreajuste o
  diferencia entre poblaciones.

8. KMODES: INTERPRETABILIDAD Y MÉTRICAS DE AGRUPAMIENTO
--------------------------------------------------------------------------------

8.1 QUÉ ES Y PARA QUÉ SE USA

KModes agrupa pacientes por similitud en variables binarias, asignando a cada uno
al cluster cuyo "centroide" (la combinación más frecuente de valores, o moda) se
le parece más. En este proyecto se usa para INTERPRETAR, no para predecir:
responde preguntas del tipo "¿qué perfiles de paciente existen y qué proporción
de cada perfil tiene dengue?".

Variables del clustering (orden fijo):
    FEATURES_KM = ["Fever", "Headache", "Myalgia", "Rash", "Outcome"]
Outcome está incluida a propósito: cada cluster es un perfil de síntomas MÁS
diagnóstico. Consecuencias que hay que explicar en la página:
  - KModes se ejecuta solo cuando el CSV trae Outcome (no se usa para diagnosticar
    a un paciente nuevo sin diagnóstico; para eso está CatBoost).
  - Que un cluster tenga mayoría de dengue NO significa que KModes "acierte":
    como Outcome es parte del agrupamiento, esa coincidencia es esperable por
    construcción. Sirve para describir, no para medir capacidad predictiva.

Modelo exportado: KModes(n_clusters=3, init="random", n_init=5, random_state=42),
entrenado con el 85% de desarrollo (df_dengue[binarias]). Se usa tal cual.


8.2 CÓMO LEER LOS 3 CLUSTERS (según el notebook)

8.4 MÉTRICAS A CALCULAR SOBRE EL HOLD-OUT

No existe "accuracy" para KModes. Se calculan estas métricas, cada una con su
lectura:

  1. TAMAÑO DE CADA CLUSTER (n y %) y comparación con el % en train.
       PSI = suma( (p_hold - p_train) * ln(p_hold / p_train) )
       (usar epsilon, p.ej. 1e-6, para evitar log(0))
     Lectura: < 0.10 estable ; 0.10-0.25 cambio moderado ; > 0.25 cambio
     importante. Responde: "¿los perfiles aparecen con la misma frecuencia en
     datos nuevos que en los de entrenamiento?"

  2. DISTANCIA PROMEDIO AL CENTROIDE ASIGNADO (costo por observación):
       cent = np.asarray(modelo_km.cluster_centroids_).astype(int)
       dist = (Xk != cent[labels]).sum(axis=1)   # cuántas variables difieren
       costo_hold  = dist.mean()
       costo_train = modelo_km.cost_ / n_train    (guardar en metadata.json)
     Rango: 0 (todos idénticos a su centroide) a 5 (difieren en todo).
     Lectura: cuanto más bajo, más "compacto" el cluster. Si en hold-out es
     claramente mayor que en train, los pacientes nuevos encajan peor en los
     perfiles aprendidos.

  3. SILHOUETTE con distancia de Hamming (la misma del notebook):
       silhouette_score(Xk, labels, metric="hamming")
       silhouette_samples(...) -> promedio por cluster
     Rango -1 a 1. Referencia del notebook: > 0.7 estructura fuerte ;
     0.5-0.7 razonable ; 0.25-0.5 débil ; < 0.25 sin estructura.
     Lectura: qué tan separados están los perfiles entre sí. Comparar contra la
     silhouette de train guardada en metadata.json. Requiere al menos 2 clusters
     presentes y menos clusters que filas; si no, devolver null con aviso.

  4. PERFIL DE CADA CLUSTER EN HOLD-OUT (lo más importante para interpretar):
       - Proporción de 1s de cada variable (Fever, Headache, Myalgia, Rash,
         Outcome) dentro de cada cluster = las barras apiladas del notebook.
       - Moda por cluster, para verificar que coincide con el centroide del
         modelo (si coincide, el perfil se mantiene en datos nuevos).
       - % de dengue (Outcome = 1) en cada cluster.

  5. COINCIDENCIA CLUSTER vs DIAGNÓSTICO (descriptiva):
       - Pureza = suma(máx. conteo de clase por cluster) / n
       - NMI (normalized_mutual_info_score) y ARI (adjusted_rand_score)
         entre labels y Outcome.
     Lectura: cuánto de la división en clusters se alinea con el diagnóstico.
     Es esperable que den altos porque Outcome es parte del agrupamiento
     (ver 8.1). Mostrarlas como información descriptiva, con una nota que lo
     aclare, y NO como medida de rendimiento predictivo.

  6. DISTRIBUCIÓN DE CLUSTERS POR SUBGRUPO (source, Gender) si esas columnas
     están presentes y hay n >= 30 por subgrupo.


8.5 CÓMO PRESENTARLO EN LA PÁGINA

  - Tabla de clusters: nombre, n, %, % de dengue, frase del centroide.
  - Barras apiladas de proporción de cada variable por cluster.
  - Semáforo simple de estabilidad (PSI, costo y silhouette vs train).
  - Texto fijo visible: "KModes es una herramienta descriptiva para entender

10. RIESGOS Y BUENAS PRÁCTICAS
--------------------------------------------------------------------------------

  1. No tunear con el hold-out: ni umbral, ni hiperparámetros, ni selección de
     variables. Si se reentrena, hacerlo solo con el 85% de desarrollo.
  2. Duplicados entre desarrollo y hold-out: el dataset tiene pocas variables y
     varias binarias, así que es probable que existan filas idénticas en ambos
     conjuntos (df_dengue.duplicated().sum() ya se mira en el notebook). Eso
     puede inflar las métricas del hold-out. Verificar cuántas filas del
     hold-out aparecen exactamente en el conjunto de desarrollo.
  3. Hold-out chico -> métricas ruidosas. Por eso los IC por bootstrap.
  4. Fever tiene definiciones distintas según la fuente (source). Mirar las
     métricas por source antes de concluir que el modelo generaliza.
  5. Datos con Platelet_Count y WBC_Count: están en el CSV pero NO los usa
     ningún modelo desplegado (en el notebook quedaron comentadas en
     'numericas'). No exigirlos.
  6. Si la clase positiva es "no detectar dengue = grave", priorizar Recall y F2
     por sobre Accuracy en la lectura de resultados.
  7. KModes es descriptivo: no presentar sus resultados como rendimiento
     predictivo ni compararlos contra CatBoost.
  8. Registrar (log) cada evaluación: fecha, nombre de archivo, hash del CSV,
     versión del modelo y métricas, para trazabilidad.

from sklearn.metrics import (confusion_matrix, accuracy_score, precision_score,

    normalized_mutual_info_score, adjusted_rand_score)

FEATURES_CB = ["Fever_Duration","Age","Headache","Myalgia","Rash","Fever"]
FEATURES_KM = ["Fever","Headache","Myalgia","Rash","Outcome"]

def metricas_catboost(model, df):
    X, y = df[FEATURES_CB], df["Outcome"].astype(int)
    proba = model.predict_proba(X)[:, 1]
    pred  = model.predict(X)
    tn, fp, fn, tp = confusion_matrix(y, pred, labels=[0, 1]).ravel()
    return {
        "confusion_matrix": dict(tn=int(tn), fp=int(fp), fn=int(fn), tp=int(tp)),
        "accuracy": accuracy_score(y, pred),
        "error_rate": 1 - accuracy_score(y, pred),
        "precision": precision_score(y, pred, zero_division=0),
        "recall": recall_score(y, pred, zero_division=0),
        "specificity": tn / (tn + fp) if (tn + fp) else None,
        "npv": tn / (tn + fn) if (tn + fn) else None,
        "f1": f1_score(y, pred, zero_division=0),
        "f2": fbeta_score(y, pred, beta=2, zero_division=0),
        "balanced_accuracy": balanced_accuracy_score(y, pred),
        "mcc": matthews_corrcoef(y, pred),
        "roc_auc": roc_auc_score(y, proba) if y.nunique() == 2 else None,
        "pr_auc": average_precision_score(y, proba) if y.nunique() == 2 else None,
        "brier": brier_score_loss(y, proba),
        "classification_report": classification_report(
            y, pred, digits=4, output_dict=True, zero_division=0),
    }

def metricas_kmodes(km, df, props_train=None):
    Xk = df[FEATURES_KM].astype(int).values
    labels = km.predict(Xk)
    cent = np.asarray(km.cluster_centroids_).astype(int)
    dist = (Xk != cent[labels]).sum(axis=1)
    out = {
        "tamano_clusters": pd.Series(labels).value_counts().sort_index().to_dict(),
        "costo_por_obs_holdout": float(dist.mean()),
    }
    if 1 < len(np.unique(labels)) < len(Xk):
        out["silhouette_global"] = float(
            silhouette_score(Xk, labels, metric="hamming"))
        s = silhouette_samples(Xk, labels, metric="hamming")
        out["silhouette_por_cluster"] = {
            int(c): float(s[labels == c].mean()) for c in np.unique(labels)}
    y = df["Outcome"].astype(int).values
    out["nmi_vs_outcome"] = normalized_mutual_info_score(y, labels)
    out["ari_vs_outcome"] = adjusted_rand_score(y, labels)
    return out
